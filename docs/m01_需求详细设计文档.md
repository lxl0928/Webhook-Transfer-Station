# Webhook 中转站需求详细设计

版本：1.1。角色：产品经理。本文定义本次可交付范围及验收标准。

## 1. 产品目标

让管理员将 Gitee 仓库事件、夜莺告警与其他服务回调转换为团队可读的群消息：统一接收回调，根据规则调用用户配置的 LLM，再发送至飞书、企业微信或钉钉自定义群机器人。每条已通过鉴权（Gitee 另含仓库校验）的消息可追踪输入、输出、状态与耗时。

## 2. 角色与范围

- 内置管理员：首次初始化自动创建，默认用户名 `admin`，默认密码 `Admin#123.`。支持修改资料、密码和个人 LLM 配置。无公开注册、无多角色权限管理页面。
- 源站：Gitee、夜莺与通用服务回调，共用唯一 URL；Gitee 保留仓库事件校验，通用服务不要求仓库字段。
- 目标平台：飞书、企业微信、钉钉群机器人，第一期发送纯文本消息；模板由服务端封装成各平台 JSON。
- 运维：部署服务、管理允许访问的 LLM 域名、数据库备份和加密密钥。

数据层按所属用户隔离；虽然仅提供内置管理员，管理接口不能跨用户读取规则或日志。

## 3. 用户流程（以 Gitee 为例，其他源站见第 8 节）

1. 在目标平台群中创建机器人，取得 Webhook URL。使用签名校验的飞书、钉钉机器人还需取得签名密钥。
2. 登录中转站，在个人设置中修改默认密码，填写 LLM Host、API Key、模型名称并保存。
3. 点击检测已保存配置，确认模型可调用。检测可能消耗少量模型额度。
4. 新增中转规则，填写名称、仓库页面地址、回调密钥、关注事件、源站模板、LLM 提示词、目标平台与目标模板。
5. 保存后系统生成随机且唯一的 `wid`，展示 `{PUBLIC_BASE_URL}/webhooks?wid=<32位随机标识>`。实际 URL 的参数值不带引号。
6. 将 URL 和相同的回调密钥填入 Gitee 仓库 WebHook 设置，启用对应事件。
7. 触发事件，在消息日志中查看状态、输入、LLM 结果、实际目标消息及平台响应摘要。
8. 失败时先检查原因与目标群是否已经收到消息，再选择重试。

## 4. 功能需求

### 4.1 登录与个人设置

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| U01 | 用户名和密码登录，返回 JWT | 正确凭证可登录；错误凭证返回 401；超过限流返回 429 |
| U02 | 修改真实姓名、手机号 | 保存后刷新仍保留；用户名不支持修改 |
| U03 | 修改密码 | 校验旧密码；新密码至少 10 位；修改后旧 Token 失效 |
| U04 | 配置默认 LLM | Host、Key、模型可保存；Key 不明文回显，空白不覆盖 |
| U05 | 退出登录 | 撤销当前用户全部已有 Token，清除浏览器会话凭证 |
| U06 | 检测服务 | 可检测后端与数据库；独立按钮对已保存的 LLM 配置发起真实调用 |

### 4.2 中转规则管理

字段包含名称、源站类型（Gitee / 夜莺 / 通用）、源站地址、鉴权模式与 Header 名称、附加信息 JSON、源站回调密钥、事件列表、源站消息模板、LLM 开关与提示词、目标类型、目标消息模板、@人员配置、目标 URL、可选签名密钥、启用状态。系统维护所属用户、创建时间、更新时间和 wid。

支持分页、按名称搜索、新增、查看、编辑、删除、复制回调 URL、跳转当前规则日志。编辑时密码字段不回显，未提供表示保留；切换目标平台必须提供新 URL。API 可显式清空可选目标签名密钥。

停用或删除规则阻止后续新回调；已接受的队列任务仍按接收时的快照继续处理。删除不删除日志。生成的 wid 在编辑时保持稳定；需要更换入口可删除并新建规则。

### 4.3 事件范围

| Gitee Header / 内容 | 内部事件 | 处理 |
| --- | --- | --- |
| `Push Hook` | push | 代码提交 |
| `Push Hook` 且 ref 为 `refs/tags/…`，或 `Tag Push Hook` | tag | 标签变更 |
| `Merge Request Hook` / `Pull Request Hook` | pull_request | PR 创建、更新、合并等，以原始载荷为准 |
| `Note Hook` / `Comment Hook` | comment | 评论与 Review Comment，保留原始上下文 |
| 其他事件或未选中的事件 | unsupported / 对应事件 | 记录 ignored，不调用模型，不发送 |

评论采用统一事件分类，不限制只有 Review Comment，避免遗漏 Gitee 不同评论载荷。仓库地址优先从 `repository.html_url` 读取，兼容 `repository.url`；忽略末尾 `/` 与 `.git` 后比较。

### 4.4 模板与 LLM

源站模板先产生模型输入，LLM 提示词作为 system message，源站渲染结果作为 user message。目标模板渲染后由平台适配器包装成文本消息。

| 变量 | 内容 |
| --- | --- |
| `{{payload}}` | 去除已识别凭证字段后的源站 JSON 文本 |
| `{{event}}` | 内部事件类型 |
| `{{repository}}` | 配置的仓库地址 |
| `{{source_name}}` | 中转规则名称 |
| `{{llm_output}}` | 模型输出；关闭 LLM 时为源站模板渲染结果 |

不执行模板代码，不支持循环、条件、任意对象属性或二次模板展开。源站模板阶段 `llm_output` 为空。附加信息可通过 source_info 及其 JSON 路径显式加入模型输入；支持 payload JSON 字段与数组下标取值。模型 ID 由用户提供，不假设所有服务商支持同一个模型。

### 4.5 日志与重试

列表支持 wid、状态、Trace ID、接收时间范围和分页筛选；详情展示原始业务输入、处理结果、目标 JSON、状态、错误、尝试次数、接收/开始/投递/结束时间及耗时。时间存储为 UTC，界面按浏览器时区显示。

状态：`pending → processing → succeeded / failed`；非订阅事件直接 `ignored`。失败消息可手动 `failed → pending`。重试使用原快照，次数累加，本版日志详情呈现最近一次尝试的结果，不提供逐次尝试历史。

为避免网络超时后重复通知，不做隐式自动重试。worker 中断的处理中任务在租约到期后标记失败；结果可能未知，管理员需确认后重试。已成功/处理中/忽略消息不能直接重试。

## 5. 非功能要求

- 接收和处理解耦：回调提交入库后，Gitee 返回 202，夜莺/通用返回 200；均表示接受而非投递成功。
- 唯一入口：wid 为随机 UUID4 的 32 位 hex 字符，数据库主键防止重复。
- 回调校验：密钥、仓库一致性、最大 1 MiB 请求体；不接受任意互联网发来的未验证业务输入。
- 密码采用带随机盐、600000 次 PBKDF2-SHA256；不使用可被快速离线撞库的裸 SHA256。
- Key、目标 URL、回调密钥、签名密钥和队列配置快照使用 Fernet 加密。
- 使用 X-Trace-Id 贯穿浏览器/API/队列/外发请求；请求结束日志包含耗时。
- 管理接口遵循 REST 资源路径与 HTTP 状态码，原生 `/docs` 暴露 OpenAPI。
- Python 通过 Ruff、pytest，Vue/TypeScript 通过 ESLint、类型检查与生产构建。
- Docker Compose 包含前端 nginx、API、worker、PostgreSQL 和一次性迁移服务。

## 6. 边界与约束

支持 OpenAI Chat Completions 兼容接口、Gitee / 夜莺 JSON WebHook、通用 JSON/文本/表单回调及三种目标的文本与 @ 人员。没有 SSE、工具调用、多模态、卡片编辑器、附件、模型自动回退、用户注册和多租户管理 UI。

网络投递不承诺 exactly-once。仅在源站提供 `X-Gitee-Delivery` 时按 `(wid, delivery_id)` 去重；没有该 Header 时将每个回调视为独立消息，不能声称 Gitee 总是提供该 Header。

密钥字段脱敏不等于业务内容匿名化：提交信息、作者、评论与代码仓库元数据仍可能包含敏感信息，并会发送至用户选择的 LLM。日志按用户权限提供查询，运维应根据实际业务制定保留期。

## 7. 验收清单

- 全新数据库迁移后可使用内置账户登录。
- 新增规则后获取唯一 URL，刷新后规则仍存在。
- 回调提交成功后先查询 pending，再经 worker 更新为 succeeded。
- 三个平台的消息 JSON、成功码和签名通过模拟 HTTP 测试。
- 错误密钥、越权、非法目标地址、无效模板不被接受。
- 非法业务码不会被误标记为 succeeded；失败输入和已生成输出可查询。
- 用户修改密码、退出后旧 Token 无法再访问管理接口。
- 日志列表与详情可定位 Trace ID；响应 Header 与输入 Trace ID 一致。
- 可通过 README 完成环境初始化、构建、启动、测试和备份。

## 8. 多源回调与 @ 人员扩展

规则新增 `source_type`（默认 API 兼容 Gitee，UI 默认通用）、`source_auth`、`source_token_header`、`target_mentions`。Gitee 地址必填且校验仓库；其他源站地址可空，仅作元数据。鉴权可选密钥 Header、Bearer 或 URL token，均必须配置密钥。通用源站支持 JSON、UTF-8 纯文本及 URL 编码表单，夜莺支持 JSON 单条与批量；不支持附件、XML、GET challenge 或未适配的专有签名。

非 Gitee 的 events 空数组表示全部；夜莺归一为 alert、recovery 或 alert_batch，批量按一条消息处理；通用事件来自 X-Webhook-Event、event_type/event，缺失或不合标识格式的载荷字段回退 webhook。不再强制仓库字段。

@ 人员可按群机器人配置 user_ids、mobiles 或 all，默认不 @。飞书 user_ids 限 Open ID 且不支持手机号；企业微信/钉钉支持用户 ID 与手机号。all 与具体成员互斥，每种标识最多 100 个并去重。前端编辑可回显/修改/清空，切换平台重置名单。名单由系统在 LLM 完成后拼装，不依赖模型生成；最终日志含 @ 配置产生的实际 payload。可用人员与 @所有人权限由对应平台控制。

新增验收：三个目标分别验证指定用户、手机号（支持的平台）、@所有人和无 @；非 Gitee 不含 repository 也可处理；三种鉴权均验证正确/错误密钥；通用对象/数组/文本/表单及夜莺告警/恢复/批量均可查日志；配置快照中的人员名单不受后续编辑影响。

## 扩展：Skill 与自然语言交互

新增独立 Skill 管理模块和登录后全局右下角聊天助手。Skill 支持内置分模块能力、自定义说明与工具权限、编辑、启停、删除自定义项、恢复内置默认、导出。聊天使用用户默认 LLM，支持持久化历史、指定 Skill、查询平台数据和生成修改操作。修改必须通过可审核的确认卡执行，凭证由独立表单输入。完整需求与边界见 [m04](m04_Skill与智能助手设计文档.md)。

## 扩展：源站回调鉴权开关

每条规则新增 source_auth_enabled，默认 true，迁移 0004 保持已有规则鉴权开启。false 时不要求源站回调密钥，依靠有效 wid 定位规则；其并不证明调用方身份。其他消息校验、管理接口 JWT、目标机器人签名不变。关闭保留旧密钥，开启必须配置有效密钥。规则表单与聊天工具均支持此字段。
